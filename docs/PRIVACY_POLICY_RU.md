## 2. Какие данные мы обрабатываем

### 2.1. Данные о товарах и ценах

- названия, артикулы, URL карточек;
- текущие и исторические цены, скидки;
- результаты сравнения между маркетплейсами;
- список отслеживания и целевые цены;
- настройки порогов уведомлений;
- история цен (локально и, при входе и серверном мониторинге, в облаке `product_price_history` — пока действует аккаунт / список отслеживания).

**Где:** локально (`chrome.storage`) и, при входе в аккаунт, в облаке Supabase (`tracked_products`, при серверном мониторинге — также `product_price_history`). Снятие с отслеживания может оставить на сервере soft-delete (tombstone) до удаления аккаунта.

Общие (не персональные) данные сопоставления товаров между площадками (id/URL, confidence) могут храниться для улучшения сравнения.

### 2.2. Отзывы и AI-анализ

При AI-анализе (в расширении или в Telegram-боте алертов) на Edge-прокси → провайдерам AI могут уходить:

- тексты отзывов (ограниченная выборка за запрос);
- краткие поля товара (название, артикул, маркетплейс, текущая/старая цена);
- фрагменты истории цен (если есть);
- данные сравнения офферов (названия, рейтинги, цены);
- в режиме «вопрос AI» в Telegram: ваш вопрос, недавний контекст Q&A и кэшированный анализ.

Тексты отзывов также могут временно храниться в общем кэше. Результат анализа — в общем `product_cache` (актуальность ~7 дней; устаревшие записи периодически удаляются) по паре «маркетплейс + идентификатор товара» — без привязки к вашему email.

API-ключи AI **не хранятся** в расширении.

### 2.3. Аккаунт (опционально)

Через Supabase Auth: email, UUID пользователя, токены сессии (локально). Пароли в открытом виде мы не храним.

### 2.4. device_id и лицензия

Случайный UUID на устройстве: лимиты AI, привязка лицензии, телеметрия. С личностью не связан, пока вы не вошли в аккаунт.

При активации Premium **ключ лицензии** может храниться локально в расширении до деактивации или удаления расширения.

### 2.5. Telegram (опционально)

Если вы указываете Chat ID и подключаете уведомления:

| Данные | Назначение |
|--------|------------|
| `telegram_chat_id` | Доставка алертов о цене и сообщений бота |
| Сессия текущего товара | Кнопки карточки AI в боте |
| Треды AI-чата (~48 ч, затем purge) | Ответы на вопросы по сохранённому анализу |
| Текст обращений / username / имя из Telegram | Поддержка и пересылка оператору |

Боты: **@PriceGuardAlertsBot**, **@priceguard_supportbot**. Chat ID не продаётся.

**Чтобы остановить обработку Telegram:** отключите Telegram в **Настройках** расширения (нужен вход в аккаунт, чтобы Chat ID снялся на сервере). Удаление диалога с ботом **само по себе** не снимает Chat ID и не останавливает серверный мониторинг.

### 2.6. Серверный скрапинг (Scrappey)

Сервер может запрашивать страницы/данные карточек через **Scrappey** (URL карточки → HTML/контент) для площадок с антиботом (**Wildberries, Ozon, Яндекс.Маркет** — не для опциональных tab-only площадок), когда:

- включён Telegram-мониторинг цен по отслеживаемым товарам этих площадок; и/или
- авторизованный **Premium**-пользователь запускает серверный unlock карточки/оффера или серверный verify в compare-research.

Cookies браузера **не** передаются. Кэш цены ~6 часов (устаревшие строки периодически удаляются). В схеме настроек могут оставаться неиспользуемые legacy-поля scraper-ключей — текущий код их не применяет.

Доступ расширения к страницам дополнительных магазинов (Мегамаркет, AliExpress, М.Видео/Эльдорадо, DNS, Ситилинк, Lamoda) используется для локального чтения публичных данных карточки/поиска **только если пользователь включил площадку в настройках «Где искать»** (или открыл её вкладку). Эти площадки **не** участвуют в серверном Scrappey-мониторинге Telegram.

### 2.7. Телеметрия, обратная связь по матчингу и диагностика

При входе в аккаунт можем обрабатывать:

- лог AI-запросов (провайдер, успех, длительность — без полных промптов);
- события «оригинал» и версию расширения;
- **match feedback** (принятые/отклонённые кандидаты сравнения: ID/URL и confidence) для улучшения общих cross-marketplace mappings;
- **compare-research** (название товара и URL источника для серверного SERP).

Краткие итоги поиска (marketplace, успех, время, усечённый запрос) могут писаться в `search_metrics`. Подробные WARN/ERROR хранятся **на устройстве** по умолчанию. Выгрузка в `telemetry_events` — **opt-in**, доступна только в developer-панели диагностики (обычным пользователям не показывается). Без текста AI-промптов и email; возможны `device_id` / `user_id`, коды ошибок и хеш запроса.

**Автоматические отчёты об ошибках** (без диалога подтверждения): при неожиданных ошибках расширения клиент может вызвать Edge `support-notify` с полями: текст ошибки (до **800** символов), опциональный контекст (до **200**), **версия** расширения и **userId** (если есть вход). Ожидаемые UX/auth-сообщения отфильтровываются на клиенте; есть rate-limit. Дальше — оператору через Telegram.

Не передаём полную историю браузинга и данные карт.

### 2.8. Платежи Premium (ЮKassa)

Обрабатывает **ЮKassa**. Номер карты мы **не** храним. Для оплаты можем передавать и сохранять: план, сумму, статус, session id, **email аккаунта**, **UUID пользователя** (в т.ч. в metadata / чеке ЮKassa). После оплаты — данные привязки лицензии. Записи платежей могут сохранять email после удаления auth-пользователя (user_id обнуляется); по запросу на удаление оператор очищает их по runbook.

### 2.9. Партнёрские метки в ссылках (опционально)

Технические параметры партнёра к ссылкам на товары (локальные настройки). Отдельный сбор ПДн для рекламы третьим лицам не ведётся.

### 2.10. Сайт и cookies

Сайт: при необходимости техническое хранилище браузера для навигации / возврата оплаты. Расширение: `chrome.storage`; permission `cookies` не запрашивается; значения cookie не отправляются на серверы PriceGuard/AI/Scrappey. Запросы к API маркетплейсов в браузере могут использовать сессию сайта локально.

Маркетинговые рассылки без согласия не отправляем.

## 5. Сроки хранения

- аккаунт и лицензия — пока действует аккаунт/подписка и разумный срок после;
- локальные данные — до удаления расширения или очистки storage;
- облачная история цен — пока действует аккаунт / список отслеживания;
- периодическая очистка: `product_cache` старше ~7 дней; `price_scrape_cache` старше ~6 часов; истёкшие `telegram_ai_threads` (~48 ч); `ai_request_log` / `search_metrics` старше ~90 дней.

Служебные логи могут храниться для эксплуатации и безопасности и удаляются по запросу на удаление аккаунта и/или периодической очисткой выше.

## 6. Ваши права и удаление

Вы можете запросить доступ, уточнение, ограничение или удаление данных, связанных с аккаунтом.

**Как удалить:** напишите на priceguardAlsupp0rt@yandex.ru с темой «Удаление данных» и укажите email аккаунта. Локальные данные удаляются с расширением. Один выход из аккаунта не очищает список отслеживания и кэши.

Telegram: отключите в **Настройках** (войдя в аккаунт). Общие кэши товаров и таблицы сопоставления — не персональные данные аккаунта. После удаления Auth-пользователя часть записей может остаться с null `user_id` (например device_id в метриках, email в платежах до scrub по запросу).
